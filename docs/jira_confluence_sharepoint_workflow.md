# Requirements-to-Reporting Workflow

1. **Jira intake:** capture stakeholder, problem statement, priority, owner, acceptance criteria, dependencies, and target release.
2. **Clarification:** log open questions and decisions; keep one requirement per traceability row.
3. **Confluence specification:** document source fields, business definitions, transformation rules, DAX measures, visuals, refresh expectations, and access controls.
4. **Implementation:** use versioned source files and keep transformation logic reviewable.
5. **QA/UAT:** map each requirement to a test case and attach reconciliation evidence.
6. **SharePoint publishing:** publish the approved report link, versioned user guide, known limitations, and support contact.
7. **Adoption:** demo key workflows, collect feedback, and track active usage rather than assuming adoption from attendance.

The sample repository contains templates only; it does not connect to Jira, Confluence, SharePoint, or a live Power BI tenant.
